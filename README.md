## Token structure

### Naming convention

CSS custom property names follow the W3C DTCG JSON path:

```
color.input.border.focus → --tek-color-input-border-focus
fonts.text.size.md       → --tek-fonts-text-size-md
colors.neutral.500       → --tek-primitive-color-neutral-500
```

### Primitives (`src/primitives/`)

Raw values. Not used directly in components.

| File | Contents |
|---|---|
| `color.json` | Neutral scale (100–900, black, white), brand, UI states, backdrop/shadow |
| `fonts.json` | Family, text scale (xs–5xl), heading scale (2xs–5xl) |
| `border.json` | Border radius and width |
| `spacing.json` | Spacing scale |

### Semantic (`src/semantic/`)

Alias tokens. What components actually use.

| File | Contents |
|---|---|
| `tokens.json` | Dark mode (default) |
| `tokens.light.json` | Light mode overrides |

Both files are auto-generated by Token Push on every push.

## Knowledge corpus

Alongside the design system, this repo holds a structured-markdown corpus of the legacy Tek products being modernized — one folder per *subject* (product, internal service, repo, or competitor) under [`corpus/sources/`](./corpus/sources/), with screens, walkthroughs, hardware views, manuals, APIs, and code snapshots all in a locked markdown format. Interpretation reports (DS gap analyses, redesign briefs, competitive comparisons) live separately under [`audits/`](./audits/) and are dated, disposable.

**Corpus vs. RAG.** The corpus is the *asset* — the durable markdown. RAG is one *technique* for consuming it (others: Claude Code reading files directly, grep, the MCP endpoint below).

Authoring is shipped: drop a pile of mixed files into [`corpus/_inbox/`](./corpus/_inbox/), run `/corpus-intake`, and a routing plan sorts them into the right per-product `uploads/<class>/` folder; per-class processing skills (`/document-screens`, `/document-pdf`, `/document-walkthrough`, etc.) then turn them into the corpus markdown.

Read [`corpus/README.md`](./corpus/README.md) for the layout, workflow, and corpus-vs-audit boundary; [`audits/README.md`](./audits/README.md) for the audit types.

## Tek MCP Endpoint

The design system and corpus are queryable by any MCP client — Claude Code, claude.ai, Cursor, Hermes — through one hosted URL (shipped 2026-07-16). Tools: token search/lookup (dark + light values), the full component API surface, and hybrid semantic + full-text corpus search with reranking and repo-path citations.

- The repo is the library; a Neon (pgvector) database is the card catalog, re-derived by [`.github/workflows/ingest.yml`](./.github/workflows/ingest.yml) on every push to `main`.
- Access is a secret URL — ask Bryan for it and treat it like a password (never commit it). In this repo, copy [`.mcp.json.example`](./.mcp.json.example) to `.mcp.json` (gitignored) and Claude Code sessions auto-connect.
- Server app: [`apps/mcp/`](./apps/mcp/) (Next.js on Vercel). Setup per client, ingestion detail, and the eval harness: [`apps/mcp/README.md`](./apps/mcp/README.md). Architecture and phasing: [`docs/mcp-server-plan.md`](./docs/mcp-server-plan.md).

## Dark / Light mode

Dark is the default. Light overrides the same CSS custom property names:

```css
/* Dark default on :root */
--tek-color-modal-background-default: #181818cc;

/* Light override — same name, different value */
[data-theme="light"] {
  --tek-color-modal-background-default: #cccccccc;
}
```

Set `data-theme="light"` on `<html>` to activate light mode. CSS custom properties cascade into shadow DOM automatically — no component changes needed.

```js
document.documentElement.setAttribute('data-theme', 'light');
```

The `tek-footer` `left` slot holds the theme toggle on all preview pages.

## Fonts

### Geist (body / UI text)

[Geist](https://vercel.com/font) — Vercel's open-source variable font.

```bash
npm install geist
```
```css
@import 'geist/font';  /* production */
font-family: var(--tek-fonts-family-geist);
```

### Geist Mono (code / monospace)

Mono type scale (`text/mono/*`) uses the same size tokens as the text scale — just with `--tek-fonts-family-mono` as the family. No separate size vars needed.

```css
font-family: var(--tek-fonts-family-mono);  /* 'Geist Mono', monospace */
font-size: var(--tek-fonts-text-size-sm);   /* same size tokens as text scale */
```

### Archivo (headings / button labels)

Variable width axis. `wdth 120` on all headings and buttons.

```css
font-family: var(--tek-fonts-family-archivo);
font-variation-settings: 'wdth' 120;
```

## How to update tokens (designer workflow)

1. Change variables in the **DS-v2 Figma file**
2. Open **Plugins → Development → Token Push**
3. Click **⬆ Push Tokens to GitHub**
4. All files turn green — `semantic/tokens.json` (dark) and `semantic/tokens.light.json` (light) both commit
5. `Publish @bbkemp/tokens` fires automatically

Both modes export in one push — no mode-switching in Figma needed.

## Using tokens

The token package has two layers. **Most projects need both.**

### Quick start — single import (recommended)

```css
@import '@bbkemp/tokens/css/complete';
```

`css/complete` includes everything in one file:
- All primitives: font families, type scale, spacing, border radius/width, color palette
- Semantic dark tokens (`:root` default)
- Semantic light tokens (`@media prefers-color-scheme` + `[data-theme="light"]` override)

### Fine-grained imports

```css
/* Primitives only — raw values, no mode switching */
@import '@bbkemp/tokens/primitives/css';

/* Semantic only — dark + light, no primitives */
@import '@bbkemp/tokens/css/combined';

/* Semantic dark only */
@import '@bbkemp/tokens/css';

/* Semantic light only */
@import '@bbkemp/tokens/css/light';
```

> **Why two layers?** Primitives (`--tek-spacing-s05`, `--tek-borders-radius-full`) are raw
> values that never change between modes. Semantic tokens (`--tek-color-input-border-focus`)
> are aliases that swap between dark and light. `css/complete` wraps both in the right order.

### Example

```css
.my-component {
  padding: var(--tek-spacing-s05, 8px);
  border-radius: var(--tek-borders-radius-03, 5px);
  border: 1px solid var(--tek-color-input-border-default);
  font-family: var(--tek-fonts-family-geist);
  font-size: var(--tek-fonts-text-size-md);
  color: var(--tek-color-input-text-default);
}
```

## Motion

### Current: AutoAnimate

[AutoAnimate](https://auto-animate.formkit.com) — 2KB, zero config. Smooths child additions/removals in light DOM containers.

**Constraint:** AutoAnimate only works on light DOM parents. Cannot cross shadow DOM.

### Planned: Motion.dev

[Motion.dev](https://motion.dev) for deliberate, choreographed animation. Adoption path:

1. Define a `Motion` collection in Figma Variables
2. Token Push exports it to `primitives/motion.json` automatically
3. Style Dictionary outputs `--tek-motion-duration-fast` etc.
4. Devs use those vars inside Motion.dev calls

### Planned: Blur tokens

The `backdrop-dark` / `backdrop-light` alpha color tokens signal that `backdrop-filter: blur()` is intended. A future `blur/` primitive collection will tokenize blur amounts:
```
blur/sm → 8px
blur/md → 12px  ← current modal value
blur/lg → 20px
```
Once defined in Figma Variables, Token Push will export them automatically. Components will reference `--tek-blur-md` in their `backdrop-filter` declarations.

## Shadow DOM cascade — CSS reset gotcha

**Do not use `* { padding: 0; margin: 0 }` as a global reset in pages that consume `@bbkemp/ui`.**

Light DOM styles targeting a custom element host (via `*`) **always override** the component's own shadow DOM `:host` rules. This means `* { padding: 0 }` silently zeroes out the padding on `tek-modal`, `tek-input`, `tek-button`, and every other component — even though the tokens resolve correctly.

The symptom is invisible in code: tokens load, the component is in the DOM, but everything looks flat and borderless.

**Correct pattern:**

```css
/* Safe — box-sizing does not interfere with :host padding */
*, *::before, *::after { box-sizing: border-box; }

/* Scope margin/padding reset to standard HTML elements only */
body, h1, h2, h3, h4, h5, h6, p, ul, ol, li,
blockquote, figure, figcaption, dl, dt, dd, pre { margin: 0; padding: 0; }
```

**Why `gap` works but `padding` doesn't:** Common resets zero `padding` and `margin` but not `gap` — so component gaps appear correct while all padding is missing.

## tek-input state management — developer note

- **`_render()`** — full `innerHTML` replacement. Called on `connectedCallback` and structural `attributeChangedCallback` changes only.
- **State changes (`focus`, `filled`, `default`) do not trigger `_render()`** — they are handled entirely by `:host([state=...])` CSS selectors. Re-rendering on state change would destroy the focused `<input>` mid-typing.

Focus/blur listeners are re-attached after each `_render()`. They update the `state` attribute directly; CSS reflects the change immediately without touching the DOM.
